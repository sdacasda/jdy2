# DAED Database Login Repair and Template Retirement Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Repair the pinned DAED management database and login path without deleting user data, prevent credentials from appearing in Web errors, provide a guarded password-recovery workflow, and completely remove the obsolete Athena configuration-template subsystem.

**Architecture:** Keep DAED as the sole owner of `/etc/daed/wing.db` and patch the immutable assembled dae-wing source before OpenWrt compiles it. Serialize SQLite access in the patched backend, sanitize the pinned DAED Web source before it is embedded, expose password recovery only through a root-owned shared shell library and write-gated ubus method, and keep the original DAED UI in the same-origin `/athena-daed/` iframe. Remove every template generator, asset, API, test, and documentation path instead of leaving an unused second configuration system.

**Tech Stack:** OpenWrt/LiBwrt package Makefiles, POSIX `sh`, Python 3 `unittest`, Go/GORM SQLite source patching, TypeScript/React source patching, LuCI JavaScript, rpcd/ubus JSON ACLs, nginx same-origin reverse proxy, GitHub Actions YAML.

## Global Constraints

- Work only in `work/v19-plan/jdy2-main`; do not edit the desktop snapshot in place and do not push GitHub.
- Preserve all pre-existing unrelated working-tree edits. At plan approval time these paths are already dirty and must be reviewed rather than overwritten: `.github/workflows/build-athena-v19.yml`, `packages/athena-runtime/files/usr/lib/athena/daed-recovery.sh`, `scripts/test_runtime_scripts.sh`, `tests/runtime/test_daed_recovery.sh`, `tests/test_runtime_runner.py`, `CHANGE_SUMMARY-v19-validation-fix.md`, and `VERIFICATION_REPORT-v19-validation-fix.md`.

- Never persist, log, serialize, or include a DAED password in a report, artifact, ubus status response, browser storage, UCI, or shell history generated by the project.
- DAED remains disabled by default and listens only on `127.0.0.1:2023`; browser-facing access remains same-origin `/athena-daed/`.
- The password reset confirmation phrase is exactly `RESET DAED PASSWORD`.
