# Athena 实时仪表盘

Athena v19 登录 LuCI 后，默认从“状态 → 概况”进入只读实时仪表盘。“服务 → Athena 优化 → 状态”也会打开同一页面。原有的路由、防火墙、系统日志、进程和实时信息页面仍然保留，可用于进一步排查。

## 采样和历史

- 页面每 3 秒读取一次本机状态。
- 浏览器内最多保留 200 个采样点，约 10 分钟。
- 刷新或关闭页面会立即清空历史。
- 采样数据不会写入闪存、数据库或日志，也不会上传到外部服务。
- 页面不加载 CDN 或外部图表库。

连续一次读取失败时，页面保留最后一次成功数据；连续两次失败后才显示“数据已中断”，以避免短暂的 rpcd 抖动造成误报。

## 卡片和图表

| 区域 | 含义 |
|---|---|
| 系统 | 运行时间、负载、内核、系统时间同步状态 |
| CPU/内存 | 相邻采样间的 CPU 使用率、当前内存占用 |
| WAN | WAN 接口、地址、链路状态和实时接收/发送速率 |
| 无线 | 三路射频、独立 2.4 GHz IoT SSID 和已连接客户端概况 |
| DAED | 安装、运行、监听和最近错误分类，不返回完整日志 |
| 加速 | NSS、Wi-Fi offload、ECM frontend 和 Flow Offload 状态 |
| 温度 | CPU、NSS 和可用无线热区温度 |

曲线包括 WAN RX/TX、CPU/内存百分比以及 CPU/NSS/Wi-Fi 温度。第一组采样没有前一个计数器可比较，因此速率显示为“—”；计数器回退时按 0 处理，不生成负值尖峰。

## 告警说明

- **DAED eBPF 不兼容**：识别 `local_tcp_sockops` 无法加载等错误。需要使用与当前 LiBwrt 6.12 内核兼容并经过来源校验的 DAED 构建。
- **系统时间未同步**：1970 年或明显无效的时间单独告警，不归因于 DAED。
- **WAN 断开**：未检测到有效 WAN 链路或默认出口。
- **DNS 异常**：只显示分类和计数，不显示查询名称或完整日志。
- **无线离线**：预期射频或 IoT SSID 不可用。
- **温度过高**：默认 80°C 告警，90°C 严重告警。

DAED 默认关闭是本项目的安全发布策略，不属于故障。导入节点和模板、完成 `athena-setup` 后再启用 DAED。

## 隐私边界

仪表盘 RPC 只读取 `/proc`、`/sys`、ubus、必要的 UCI 状态和经过分类的 DAED 错误。它不会返回或保存：

- Wi-Fi 密码；
- 节点链接、订阅地址、UUID、Token、私钥；
- 完整 DAED 日志；
- 浏览器持久历史；
- 远程遥测或外部统计。

## 恢复原 LuCI 概况页

如需临时恢复 LuCI 原生概况页，可在 SSH 中执行：

```sh
rm /usr/share/luci/menu.d/zz-athena-dashboard.json
rm -f /tmp/luci-indexcache
/etc/init.d/rpcd restart
/etc/init.d/nginx reload
```

重新安装或升级 `luci-app-athena` 会恢复 Athena 仪表盘入口。

如果主 Web 页面无法访问，请从 LAN 打开恢复入口：

```text
http://192.168.50.1:8080/
```

该入口只用于诊断和恢复，不应从 WAN 暴露。

## initramfs 真机验收

写入 sysupgrade 前，必须先用 U-Boot 启动 initramfs 并确认：

1. `192.168.50.1`、LuCI 和 `192.168.50.1:8080` 均可访问。
2. “状态 → 概况”显示新仪表盘，3 秒刷新且页面无横向溢出。
3. Argon 深色、浅色、自定义主色和移动端布局均可读。
4. WAN、CPU、内存、温度和三路 Wi-Fi 数据合理，无 `NaN`、`Infinity` 或负速率。
5. DAED 关闭时页面仍正常；启用后能显示运行状态。
6. 使用不兼容 DAED 测试时能明确显示 eBPF 告警，而不是空白页。
7. 缺少 IPv6、ECM、IoT 或部分温度传感器时，其他卡片继续刷新。
8. DAED 仍只监听 `127.0.0.1:2023`，ECM frontend 与 Flow Offload 保持停止。

只有上述项目和基础网络、三路无线、IoT SSID、DAED 面板均通过后，才可考虑刷写 sysupgrade。
